# Hik Camera SDK C++ Wrapper(相机底层c++封装)

基于海康（Hik）MVS Camera SDK 的 C++ 工业相机封装项目。项目使用面向对象的方式组织相机设备枚举、连接、参数配置、图像采集与资源释放流程，并结合 OpenCV 实现图像显示及取图失败后的重连尝试。

## 1. 项目简介

工业相机 SDK 的使用涉及设备枚举、句柄创建、设备打开、参数设置、图像缓冲区管理和资源释放等多个环节。本项目通过 `Camera` 类封装相机操作，通过 `Sdk` 类管理 SDK 的初始化与释放，并在应用程序中串联取图流程。

项目采用**单线程串行处理**，重点实践 C++ 类封装、第三方 SDK 调用、错误处理、图像数据管理及 CMake 多目录构建。

## 2. 核心功能

- **SDK 生命周期管理**：使用单例模式管理 `Sdk` 实例，封装 SDK 初始化与释放接口。
- **设备枚举与连接**：支持枚举 GigE 网口相机和 USB 相机，按设备序列号排序，并检查设备可访问性及连接状态。
- **相机参数配置**：支持设置像素格式、触发模式、GigE 数据包大小、曝光时间、增益、自动曝光和自动白平衡。
- **图像采集与显示**：通过 MVS SDK 获取图像缓冲区，将灰度图像转换为 OpenCV `cv::Mat`，并使用 `cv::imshow()` 显示。
- **运行时交互控制**：通过终端选择自动曝光、手动曝光、增益和自动白平衡；通过键盘调整曝光时间。
- **异常处理与重连尝试**：取图失败后关闭相机，重新扫描设备并尝试连接；连接成功后重新配置基础参数并启动采集。
- **错误诊断与资源管理**：检查关键 SDK 调用的返回码，并封装停止取流、关闭设备、销毁句柄及归还图像缓冲区等操作。

## 3. 技术实现

### 3.1 `Camera` 类：相机操作封装

`Camera` 类集中管理设备列表、相机句柄、相机索引和打开状态等信息，将底层 SDK 调用封装为独立接口。

| 接口 | 职责 |
|---|---|
| `scan()` | 枚举可用相机并记录设备列表 |
| `connect()` | 检查设备可访问性、创建句柄并打开设备 |
| `set()` | 配置像素格式、触发模式和 GigE 数据包大小 |
| `start_grab()` | 启动图像采集 |
| `getframe(cv::Mat&)` | 获取图像并转换为 OpenCV 格式 |
| `close()` | 停止取流、关闭设备并销毁句柄 |

另外，类中还提供曝光时间、增益、自动曝光和自动白平衡等参数设置接口。

### 3.2 `Sdk` 类：SDK 生命周期管理

`Sdk` 类通过静态局部对象实现单例实例管理，并使用 `initial()` 和 `release()` 封装 MVS SDK 的初始化与释放。`m_initialized` 用于记录初始化状态，析构函数中会调用 `release()`。

> 注意：主程序应在枚举相机前显式调用并检查 `sdk.initial()` 的返回值。仅调用 `Sdk::instance()` 不会自动执行 SDK 初始化。

### 3.3 图像缓冲区管理

程序通过 `MV_CC_GetImageBuffer()` 获取 SDK 管理的图像缓冲区，并根据图像宽度、高度和像素格式构造 OpenCV `cv::Mat` 视图。随后使用 `clone()` 创建独立的图像副本，再调用 `MV_CC_FreeImageBuffer()` 归还 SDK 缓冲区，避免后续使用图像时依赖已归还的缓冲区内存。

### 3.4 错误处理与资源释放

项目在设备枚举、句柄创建、设备打开、参数设置、启动取流和图像获取等关键步骤检查 SDK 返回值，并通过统一的错误输出函数记录操作名称、错误码及部分常见错误原因。

相机关闭流程包括停止取流、关闭设备和销毁句柄；设备打开失败时，会清理已经创建的句柄。上述处理有助于定位调用失败问题，并降低资源未释放的风险。

### 3.5 取图失败后的重连尝试

在主循环中，如果 `getframe()` 返回失败，程序会关闭当前相机，重新扫描设备并尝试连接。连接成功后，重新配置基础参数并启动采集，再进入下一轮取图。

当前实现属于基于取图失败的基础重连尝试，并不保证能够恢复所有类型的设备故障；重连后也没有重新应用全部先前的曝光、增益和白平衡设置。

### 3.6 交互式参数控制

程序支持在启动阶段通过终端配置自动曝光、手动曝光、增益和自动白平衡。在图像显示期间，可以通过 OpenCV 窗口接收按键输入：

- `q`：退出采集循环。
- `+`：增加曝光时间。
- `-`：减少曝光时间。

## 4. 项目结构

```text
camera-sdk-wrapper/
├── CMakeLists.txt
├── app/
│   ├── CMakeLists.txt
│   └── main.cpp
└── lib/
    ├── CMakeLists.txt
    ├── include/
    │   ├── Camera.h
    │   └── sdk.h
    └── src/
        ├── Camera.cpp
        └── sdk.cpp
```

- `app/`：应用程序入口，负责参数交互、取图显示和重连流程。
- `lib/include/`：相机封装类与 SDK 管理类的头文件。
- `lib/src/`：相机操作与 SDK 生命周期管理的实现。
- 根目录及子目录中的 `CMakeLists.txt`：组织应用程序和封装库的构建。

## 5. 技术栈与运行环境

- **语言标准**：C++17
- **构建工具**：CMake 3.10+
- **图像处理与显示**：OpenCV
- **工业相机 SDK**：Hikrobot MVS Camera SDK
- **开发环境**：Linux

项目当前 CMake 配置使用以下 MVS SDK 路径：

- 头文件目录：`/opt/MVS/include`
- 动态库目录：`/opt/MVS/lib/64`
- SDK 动态库：`libMvCameraControl.so`

如果 SDK 安装位置不同，需要相应修改 CMake 配置。构建前还需确保系统已安装兼容版本的 OpenCV 与 MVS SDK。

## 6. 构建与运行

在项目根目录执行：

```bash
cmake -S . -B build
cmake --build build
```

根目录的 `CMakeLists.txt` 设置项目、C++ 标准并添加 `lib` 和 `app` 子目录。项目主要包含两个构建目标：

- `camera_lib`：由 `Camera.cpp` 和 `sdk.cpp` 构建的共享库。
- `camera_app`：由 `main.cpp` 构建的应用程序。

若使用 CMake 默认的目标输出路径，可尝试运行：

```bash
./build/app/camera_app
```

如果可执行文件生成在其他位置，请以实际构建结果为准。运行完整采集流程需要连接并正确配置兼容的工业相机，同时确保系统能够找到 MVS SDK 动态库。

## 7. 项目收获

- 实践使用 C++ 封装第三方硬件 SDK，梳理设备枚举、连接、取流和关闭的基本流程。
- 理解单例模式在 SDK 实例管理中的应用，以及资源初始化与释放的基本组织方式。
- 掌握 SDK 图像缓冲区向 OpenCV `cv::Mat` 转换时的内存所有权处理。
- 通过关键节点返回码检查和失败分支清理，积累 SDK 调用问题的排查经验。
- 实践基于取图失败的重连逻辑，理解异常情况下的资源清理与恢复流程。
- 使用 CMake 组织多目录项目，实践应用程序与封装库分离的工程结构。
